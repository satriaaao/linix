# Security review — 2026-10-02

Production: rentalcamera.aiorbitlab.me. Scope: storefront/CMS HTTP handlers, Supabase row policies and admin credential flow, Maps redirects, dependency audit, basic functional regressions. No destructive exploitation or customer-data extraction was performed.

## Fixed

- Anonymous member lookup previously returned name, phone and email given a phone number. It now returns no match without an authorized admin session. Public visitors enter their own information; CRM lookups remain available to admins.
- Visitor presence rows were publicly readable/updateable. Public SELECT/INSERT/UPDATE policies removed; heartbeat uses a narrow validated RPC, while admin reporting retains its RLS read policy.
- CMS credential checking now has database-backed counters (20 checks per source per minute), shared across serverless invocations. Rejected session requests return no token and commit counters. Password digests and hashed session tokens remain unchanged.
- Review text lengths and rating/type limits enforced in database for new writes; unpublished-only public submission policy retained.
- Maps resolver validates HTTPS, hostname, credentials and port at every redirect. Responses capped at 2 MB with an 8-second deadline; internal error details removed.
- CMS rejects cross-site logout and oversized request bodies; upstream internal error details removed.
- Added HSTS, same-origin frame restrictions and script-source CSP compatible with existing modules. Private source/manifest paths resolve to custom 404.
- Committed npm lockfile, scripts-disabled installs and high-severity audit plus security regressions in deployment CI. Native npm audit reported zero known advisories in the deployed app's 14 dependencies.

## Verification

Security regression tests cover hostile Maps origins/redirects, CMS cross-site/size rejection, and heartbeat RPC routing. Existing cart, promo routing, signage authentication/database and video tests passed. Database transaction checks confirmed anonymous member/presence access denial and shared login counters; test writes rolled back.

## Limitations and follow-up

No system can be guaranteed 100% secure. This is a scoped source/configuration review, not a full penetration test or proof of absence of bugs. Known-advisory audits do not detect malicious packages. Root Next.js project is separate from the deployed static rental app and was not released by this change.

- Existing CMS sessions are bearer tokens accessible to JavaScript in localStorage; stored XSS could steal a session. Migrating all existing Supabase admin calls to a same-origin HttpOnly-cookie gateway would need dedicated compatibility testing. CSP still allows inline scripts because existing pages depend on them.
- Per-source database login limits are defense in depth; forwarded-source trust depends on the Supabase gateway. They do not replace edge-level WAF/DDOS protection or account-level monitoring. Public review/analytics/heartbeat ingestion can still attract spam; future distributed anti-bot controls should cover direct database endpoints as well as the website.
- Existing third-party CDN scripts remain pinned to repository commits but are not all vendored/SRI protected.
- Infrastructure accounts, password strength, MFA, secrets in historical commits, backup recovery, and the separate signage/report backend require their own ongoing verification. No credentials were rotated or accounts changed in this release.
- Use unique passwords and MFA on GitHub, Vercel and Supabase; monitor security events, keep dependencies current, and test backups regularly.
